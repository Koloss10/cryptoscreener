## 2. Головне рішення (що зробив би досвідчений розробник)

Digash — не статична сторінка: у нього сервер збирає потоки з 8 бірж, зберігає поминутні знімки стакана й рахує формації на сервері кожні 5 с. Статичний сайт на GitHub Pages цього не вміє: щойно закриєте вкладку, збір припиняється, а історії для симулятора й чесної статистики немає.

Тому першим кроком — **збирач даних на сервері**, а не нові екрани. Обмеження «лише безкоштовне»: варіанти — безкоштовна віртуальна машина (наприклад, Oracle Cloud Always Free) із Node-збирачем + Supabase для сховища; GitHub Actions за розкладом (раз на 5 хв, без потоків); Cloudflare Workers/Durable Objects у безкоштовних межах. Перед вибором перевірити поточні умови безкоштовних планів.

## 3. Етапи

**Етап 0. Основа (1–2 дні)**
- Розбити `app.js` (понад 1000 рядків) на модулі, прибрати залежність від CDN-стилів, додати CSP і SRI для TradingView (зауваження рецензії).
- Налаштувати CI (тести при кожному коміті), ввести єдину конфігурацію бірж.

**Етап 1. Збирач і сховище**
- Сервіс збирає тікери, свічки 1m, відкритий інтерес, фандинг, знімки стакана (раз на хвилину, топ-100 монет) і складає в Supabase (партиції за днем, строк зберігання 7–30 днів, щоб влізти в безкоштовний ліміт).
- Детектор формацій і оповіщень переїздить на сервер; браузер лише показує.

**Етап 2. Скринер рівня Digash**
- Метрики: NATR, зміна ціни на інтервалах 1m–1d, обсяг, кількість угод, сплески обсягу, OI, фандинг, відстань до рівнів, кореляція з BTC; підсвітка за порогами й градієнтом, пресети.
- Секундні таймфрейми (WebSocket Binance), гарячі клавіші (Space, Alt+1…6, Shift+D/B).

**Етап 3. Оповіщення**
- Типи: перетин ціни/лінії, плотність, сплеск обсягу, волатильність, OI, фандинг, кореляція, листинг. Канали: Telegram-бот (безкоштовно), звук, системні сповіщення.

**Етап 4. Формації, чесно**
- Спочатку виміряти кожен тип на серверній історії (з комісіями й проковзуванням), лишити лише ті, що не збиткові; решту позначити «експериментальні».
- Довести до 13 типів лише після вимірювання. Статистику 24г/7д/30д рахувати на сервері. ІІ-розбір — необов'язковий, пізніше.

**Етап 5. Конструктор екрана**
- Віджети: графік, сітка, навігація, карта плотностей, стакан, сигнали; зв'язані групи; збереження/імпорт розкладки.

**Етап 6. Симулятор ринку**
- Відтворення історії свічка за свічкою з плотностями, що були в той момент (потребує етапу 1).

**Етап 7. Біржі**
- Додати Bybit, OKX, Bitget, Gate, MEXC, Hyperliquid, Aster через шар-адаптер (формат даних єдиний). Починати з Bybit і OKX.

**Етап 8. Продукт (лише якщо потрібно іншим людям)**
- Облікові записи, тарифи, оплата, застосунок для ПК, мови й теми, юридичні тексти. Для особистого користування можна пропустити.

## 4. Ризики

- Безкоштовні ліміти сховища (стакан щохвилини дуже швидко росте) — тримати лише потрібний строк.
- Біржі обмежують частоту запитів і блокують спільні IP.
- Формації без доведеної переваги — ризик помилкового довір'я; кожну виводити з міткою, поки не виміряна.
- Юридично: не копіювати код, дизайн і тексти Digash; повторювати лише ідеї функцій.

## 5. Найближчі кроки

1. Вибрати, де працюватиме збирач (етап 1) — від цього залежить усе далі.
2. Етап 0: CSP/SRI, розбиття `app.js`.
3. Налаштувати торгівлю за інструкцією з README (кроки в панелі Supabase).
