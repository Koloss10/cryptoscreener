# CryptoScreener v6 — Veles Edition

Статичний фронтенд (без збірки): жива таблиця метрик Binance Futures, термінал із графіком, симулятор DCA-бота у стилі Veles,
бектестер із 14 комбо-фільтрами, скрінер Топ-20 та мульти-графіки TradingView.
Дані — публічний API Binance (спот). Інтерфейс українською.

## Запуск

```bash
python3 -m http.server 8080   # потім відкрити http://localhost:8080
```

Можна просто відкрити `index.html`, але кнопка «Скачати .html» (збирає один автономний файл)
працює лише через `http(s)`, наприклад на GitHub Pages.

## Вкладка «Скринер»

Топ-40 USDT-ф'ючерсів Binance за обсягом: ціна, зміна 24г/5хв/15хв/1г, обсяг 1г, сплеск обсягу
(останні 5 хв проти середнього за попередню годину), NATR 5m/14, фандинг. Дані — WebSocket
(`kline_1m` + `!miniTicker@arr` + `!markPrice@arr@1s`), метрики оновлюються раз на 2 с, при обриві
з'єднання або тиші 15 с — автоматичне перепідключення. Фільтри й сортування зберігаються в браузері.
Клік по рядку відкриває графік (для монет без споту дані беруться з ф'ючерсів).

## Вкладка «Плотності»

Крупні лімітні заявки Binance Futures для 30 найліквідніших крипто-монет: бік, ціна, розмір у $,
у скільки разів більша за медіанний рівень, відстань до ціни, «розїдання» (за скільки хвилин
плотність зʼїсть поточний обсяг торгів), скільки вона вже стоїть і глибина книги.
Ті самі лінії малюються на графіку терміналу (шар «🧱 Плотності»).

Обмеження, про які варто знати:
- Книга береться по 1000 рівнів (`/depth?limit=1000`), тому видно лише в межах колонки «Глибина книги»:
  для BTC це десяті частки відсотка, для ETH ≈ ±0.7%, для дрібних монет — кілька %.
- Монети опитуються по черзі (≈ 1 запит за 2.5 с, ≈ 20% ліміту ваги Binance), тому кожна оновлюється
  раз на ≈ 75 с; монета з відкритого графіка — частіше. Опитування йде лише коли відкрито вкладку
  «Плотності» або «Термінал».
- Заявки можуть зникнути до того, як ціна їх торкнеться. Це аналітика, а не рекомендація.

Адреса вкладки зберігається в URL (`…/#dens`, `…/#live`, `…/#terminal`).

## Вкладка «Формації»

Детектор працює на закритих 1-хвилинних свічках 40 монет зі «Скринера» (остання, що формується, не
аналізується, тож сигнали не перемальовуються). Типи: **пробій** екстремуму 60 хв з підтвердженням
обсягом, **ретест** пробитого рівня, **сплеск обсягу** з рухом ціни, **відскок від плотності** (стіна
з вкладки «Плотності» стоїть ≥ 1 хв). У кожної формації є вхід, стоп і тейк (2R).

Як рахується результат: за наступними закритими свічками до 60 хв; тейк раніше стопу — перемога (+2R),
стоп — програш (−1R); стоп і тейк в одній свічці — стоп; по закінченню часу — результат у R на момент
виходу; якщо свічок для перевірки вже немає — «невідомо» (у відсоток перемог не входить).
Комісії та проковзування не враховані. Відсоток перемог = перемоги / (перемоги + програші).

**Калібрування на реальних даних (24.11.2026).** `tools/calibrate.js` прогнав детектор і оцінку результату
ковзним вікном по 1000 реальних 1m-свічок (≈ 16.6 год) BTC, ETH, SOL, DOGE (без «відскоку від плотності» —
немає історії книги). Результат: 101 сигнал (≈ 1.5 на монету за годину), перемогли 23% при потрібних 33% для 2:1,
середній результат **−0.28R до комісії і ≈ −0.8…−0.9R після** (медіанний стоп 0.18% ціни, кругова комісія ≈ 0.1%).
Фільтр «ризик ≥ 0.3% ціни» залишив 22 сигнали з тими ж 18% перемог. Тобто на цій вибірці ці правила **програшні**;
вибірка мала (17 год, 4 монети, один ринковий режим), тому це не вирок, але й жодної підстави вважати їх
прибутковими немає. Пороги під цю вибірку навмисно НЕ підганялись (це було б перепідгоном). Не підключайте
ці сигнали до автоматичної торгівлі без власної перевірки на значно більшій історії.

Обмеження: статистика збирається лише поки сторінка відкрита і зберігається тільки в цьому браузері
(до 500 сигналів). Постійна статистика, як у Digash, потребує сервера. Це навчальна аналітика, а не рекомендація.

## Важливо знати

- **Бот — симуляція.** Ордери на біржу не відправляються, API-ключів додаток не приймає.
  Вибір біржі впливає лише на підпис; ціни завжди з Binance. Реальна торгівля потребує
  серверної частини з безпечним зберіганням ключів (наприклад, ccxt на бекенді).
- **«ДЕМО-ДАНІ»**: якщо Binance недоступний, показуються згенеровані свічки з відповідною позначкою.
- **Бектест** використовує ту саму сітку, що й вкладка бота (indent, overlap, логарифм, мартингейл),
  враховує плече, комісію та ліквідацію (втрата 90% маржі). Індикатори спрощені: «Тренд» — це
  Close відносно EMA20, «Стохастик» рахується по ціні. Це не заміна повноцінним індикаторам
  (наприклад, пакет `technicalindicators`) і не фінансова порада.
- **Скрінер Топ-20** рахує по справжніх свічках обраного таймфрейму (`analysis.js`): пробій
  екстремуму 20 свічок, свічкові патерни (поглинання, пін-бар), близькість до рівня, незакрита
  цінова прогалина (FVG) і RSI(14) за Вайлдером. Це технічні сигнали, а не рекомендації.
- Telegram-токен вводиться в браузері й іде прямо на api.telegram.org; не використовуйте
  токен, який дає доступ до чогось важливого.
